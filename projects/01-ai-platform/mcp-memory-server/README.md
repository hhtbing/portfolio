# Agent Memory Service — 跨 Agent 长期记忆与上下文服务

## 📋 项目概览

Agent Memory Service 是面向多个 AI Agent 的长期记忆与上下文服务。它统一处理记忆写入、召回、用户画像、知识关系和上下文注入，并为技能与规则提供集中管理能力。

**项目类型：** Agent 基础设施

**开发周期：** 2026 年 10 月 - 至今

**项目状态：** 生产环境

## 🎯 解决的问题

1. **跨会话上下文中断：** Agent 需要在不同任务和线程之间延续稳定的项目知识。
2. **接入方式分散：** 不同客户端通过 MCP、Hook 或 REST 提供上下文。
3. **单一检索不足：** 精确关键词、语义检索和知识关系需要组合使用。
4. **长期偏好难以治理：** 用户画像、技能和规则需要可更新、可审计的管理方式。

## ⚡ 核心特性

### 1. 多协议接入
- 支持 MCP、Hook 和 REST 接入
- 统一记忆写入、查询和会话上下文接口
- 保留来源和客户端身份信息

### 2. 混合检索
- 结合向量检索与全文检索
- 使用知识图谱补充实体和关系上下文
- 支持按标签、类型、时间和质量筛选

### 3. 上下文与画像
- 为 Agent 组织跨会话上下文
- 汇总用户偏好、工作方式和项目知识
- 支持上下文注入和受控读取

### 4. 技能与规则治理
- 集中管理技能定义和版本
- 维护分层规则和发布内容
- 支持错误模式、质量评分和人工修正

## 🏗️ 系统架构

```
Agent / 客户端
        ↓
MCP / Hook / REST 接入
        ↓
事件处理与记忆写入
        ↓
混合检索 ─ 向量 / 全文 / 知识图谱
        ↓
上下文组装 ─ 画像 / 技能 / 规则
        ↓
Agent 上下文
```

## 💡 技术亮点

- 将不同 Agent 的记忆入口统一到同一服务边界。
- 结合 `bge-m3` 语义向量、全文检索和知识关系提高召回覆盖。
- 通过画像、技能和规则把长期上下文从“可搜索”推进到“可治理”。
- 支持协议层、服务层和存储层分别验收。

## 🛠️ 技术栈

- Python / FastAPI
- MCP、Hook、REST
- SQLite、SQLite-vec、FTS
- ONNX、bge-m3
- 知识图谱、用户画像、技能与规则
